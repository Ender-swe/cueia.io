## 6. Fresh-install acceptance

Use one fresh sample deployment for cases 1–3. Retain both owners' IDs, counts, preferences, attachment metadata and bytes, three Cueia sessions, and an unexpired preview link across the restart. Keep token values out of test output. These cases follow the [proposal's acceptance sequence](proposal.md#acceptance-on-a-fresh-installation).

- [x] 6.1 **Case 1 — Alice's first visit.** From the Cueia checkout alone, install from the frozen lockfile, build from the root, configure Clerk, the sample API, and the workspace provider, start Compose, and check health and an empty exchange (401). Sign Alice in through Google. Release two session exchanges together before either can provision her. Confirm one workspace, one VM, one attached disk, and one seed set with matching thread and attachment IDs. In session A, run the Files preview journey from task 5.5 with Tasks open. Change a preference in A, read it in B, and record Alice's snapshot and file bytes.
- [x] 6.2 **Case 2 — Bob's workspace.** Sign Bob in through GitHub. Check for distinct workspace, VM, disk, thread and attachment IDs, and the default preference. Create the same relative path with different contents on both machines. Verify each owner's listing and read resolve to that owner's bytes. With Bob's bearer, request a direct read and a preview link using Alice's attachment ID. Verify both fail, then open Bob's own attachment and record his snapshot and bytes.
- [x] 6.3 **Case 3 — Recovery and revocation.** Issue Alice a preview link, restart PostgreSQL, the API, and the workspace VMs with their disks retained, and compare both owners' counts, IDs, preferences, metadata, and exact bytes. Verify directly created files survive in Files without registration. Replace Alice's VM, reattach her disk, and verify her workspace ID, file IDs, and bytes survive. Verify the pre-restart link still opens. Revoke Alice's session A and check its next snapshot returns 401 while B and Bob's session each open the correct workspace. Advance the fixture clock past link expiry while B is valid. Check the old link fails and a fresh link obtained with B returns the original PDF bytes.
- [x] 6.4 **Case 4 — Competing processes.** Start two separate Go processes on the same Docker PostgreSQL database. Wait until both have read the same eligible row and version, release them together, and assert one successful update, one loser, and one persisted version increment.
- [x] 6.5 **Case 4 — Failed deployment.** Start Compose against an isolated database with a deliberately failing fixture migration. Verify a nonzero migration exit, no API listener, and no running worker or claimed work. Exercise the startup gate in both sample and live mode.
