# Model task recovery implementation tasks

Implements [issue #10](https://github.com/Ender-swe/cueia.io/issues/10). Follow the [design](design.md), [durable task requirements](specs/durable-tasks/spec.md), [chat-result requirements](specs/task-chat-results/spec.md), and [versioned access requirements](specs/workspace-access/spec.md). Keep all Go tests in the closest `test/` directory. These boxes track implementation, not completion of the planning artifacts.

## 1. Domain contracts and persistence

- [ ] 1.1 Define task states, execution/version control preconditions, checkpoint v1, operation fingerprints, terminal outcomes, recovery/panic error classifications, and handler/review interfaces in `apps/server/internal/task/`, using `task.go` for domain structs and the session feature layout. Verify allowed transitions and unsupported checkpoint versions with focused tests under `internal/task/test/`.
- [ ] 1.2 Add additive SQL migrations for `conversations`, `tasks`, `task_runs`, and `task_attempts` from the design, including recovery-start/deadline state. Verify fresh install, repeated migration, the deferred current-run relationship, one Main conversation per workspace, one open attempt per execution, and rejection of cross-workspace relationships.
- [ ] 1.3 Add the input, operation, outcome, delivery, message, and mutation-response tables and indexes, including review run/generation bindings. Verify unique operation identities, valid review bindings, one outcome/delivery/message per execution, and workspace-scoped response keys against PostgreSQL.
- [ ] 1.4 Implement a shared authoritative clock abstraction and controlled multi-process test clock. Add worker lease/concurrency/poll configuration with validated defaults. Verify production cannot enable the test clock and invalid renewal/lease settings fail startup.

## 2. Conversation destinations and replayable requests

- [ ] 2.1 Implement minimal conversation identity storage in `internal/conversation/`: atomically ensure Main, create/list owned side conversations, and validate optional mail/event source bindings. Race first Main resolution and verify distinct owners retain distinct IDs.
- [ ] 2.2 Implement transaction-scoped idempotency reservation and saved responses, including execution/version in canonical request fingerprints and prefix-independent operation scopes. After authentication/authorization, resolve committed responses before current execution/version checks. Verify concurrent duplicates converge, payload changes return 409, rollback leaves no committed success response, and replay after restart returns the original response without mutating the new execution.
- [ ] 2.3 Implement task creation with destination resolution, initial run, optional scheduling/expiry, and saved response committed together. Test that confirmation waits for commit, absent origin uses Main, explicit invalid origin is rejected, and a lost response replays the same task ID.
- [ ] 2.4 Implement owner-scoped task list/detail reads with pagination, conversation/state/activity filters, execution number/control version, attempts, pending inputs/reviews, outcome references, and delivery status. Verify stable pagination and denial of foreign task IDs.

## 3. Worker claims and document checkpoints

- [ ] 3.1 Implement conditional task claims and attempt creation under the current run/version/status/due/expiry gates in `internal/task/memory.go`. Extend the existing separate-process claim barrier test to prove one winner, one handler entry, and one outcome for a task.
- [ ] 3.2 Implement heartbeat renewal and lease checks for every durable progress write, operation authorization, and completion. Test that expired/replaced tokens cannot update a task even if a stale handler ignores cancellation, and routine renewal/progress does not increment the owner's control version.
- [ ] 3.3 Add bounded concurrent execution and independent heartbeats to `cmd/worker`, using a connection pool and claiming only when a slot is free. Verify a blocked handler and a waiting task do not prevent an unrelated eligible task from finishing.
- [ ] 3.4 Wire the worker's workspace provider and document service with the same deployment/workspace configuration as the API. Implement checkpoint save/load, version dispatch, and owner validation of file/evidence IDs. Verify a task continues after its creator signs out without retaining that bearer token.
- [ ] 3.5 Implement expired-lease recovery and atomic graceful release, preserving interrupted attempts, original start times, and distinct finish reasons. Resume from the last compatible checkpoint within the recovery budget and fail unsupported versions before effects. Verify a new host reads the original checkpointed PDF after the path is edited/re-registered and another owner uses the same path.
- [ ] 3.6 Implement a shared transaction deadline guard using fresh database time after task/run locks. Apply it to claims, heartbeat/progress, completion, effect authorization, controls, answers, and wait/review transitions; account for undiscovered lease loss. Verify equality is expired, task expiry wins over recovery exhaustion, and held sweeps or lock waits cannot admit expired work or freeze an exhausted budget. Commit terminal outcome/delivery even when rejecting the requested mutation.
- [ ] 3.7 Catch handler-boundary panics, clean up local execution resources, and persist safe `handler_panic` failure/delivery when still eligible. Verify no automatic retry, preserved operation evidence, precedence of earlier terminal states/deadlines, and continued unrelated task execution.

## 4. Operation reconciliation and waiting

- [ ] 4.1 Implement stable operation records and fingerprint conflicts. Reuse confirmed result/file references across attempts and explicit restarts, and reconcile operations recorded after a checkpoint. Test a stop between result publication and checkpoint storage without producing a duplicate registered output.
- [ ] 4.2 Implement the review adapter contract with a durable controlled fixture for idempotent prepare, decision, dispatch authorization, receipt lookup, and pending-review invalidation. Persist preparation identity/run/generation before adapter I/O; verify response loss returns the same review, fresh reviews use a new generation, and expiry, denial, or connection-generation changes prevent dispatch.
- [ ] 4.3 Serialize effect authorization with lease ownership, deadlines, pause, and cancellation. Reconcile abandoned `authorized` records as potentially executed: reuse confirmed success, require proof excluding any old dispatch before reauthorization, otherwise persist uncertainty without resend. Kill separate workers after authorization and after provider acceptance before receipt storage; verify safe recovery and manual restart, cancellation before authorization produces zero effects, and late receipts cannot rewrite terminal outcomes.
- [ ] 4.4 Implement atomic checkpoint-and-wait transitions for input and review, releasing the lease and execution slot. Validate input schemas and persist the current pending request/review binding; verify a wait cannot bypass an elapsed deadline and unrelated tasks progress.
- [ ] 4.5 Implement bounded periodic review reconciliation independent of handler slots, with notifications only accelerating it. Recheck run/generation, eligibility, and deadlines when atomically consuming a decision and queuing continuation. Test early approval, lost notifications, duplicate passes, a crash before continuation commit, callback-free expiry, and paused decisions requiring explicit resume.
- [ ] 4.6 Implement atomic answer acceptance: validate execution/version, current request, schema, ownership, and deadlines; commit the immutable answer, service-managed checkpoint reference, queued continuation, version, and saved response together. Verify rollback, duplicate requests, worker checkpoints preserving accepted references, recovery before the next handler checkpoint, and explicit restart retaining answered rows from the prior execution.

## 5. Owner controls, retries, and scheduling

- [ ] 5.1 Implement pause, resume, and cancel checked against `expectedRunNumber` and `expectedVersion`, with replayable responses and lifecycle-only control-version increments. Close unresolved input IDs on pause/cancel, discard late answer payloads, preserve accepted answers/progress, and reissue missing input on resume. Verify pause survives restart, an old answer remains invalid after resume, and a delayed first-arrival control for an earlier execution returns 409 even when versions match numerically.
- [ ] 5.2 Implement completion/control race handling and pending review invalidation. Verify one terminal outcome when cancellation races completion, and verify approval received during pause cannot resume work or bypass revalidation on explicit resume.
- [ ] 5.3 Implement transient/safe automatic retry classification, exponential backoff, persisted recovery start/deadline, and suspension/restoration of the remaining two-minute budget. Restore the deadline when continuation is queued, or from a scheduled wait's saved due instant, rather than delaying it until claim. Verify worker restart cannot reset it, a five-minute pause preserves the remaining duration, and queued/offline time after eligibility consumes the remainder.
- [ ] 5.4 Add independent recovery-deadline and task-expiry sweeps as a complement to transaction guards, including stalled handlers and paused/waiting tasks. Save failure/expiry outcomes and reject late completions. Verify a healthy initial handler is not subject to the recovery-only two-minute limit.
- [ ] 5.5 Implement explicit restart of failed/expired tasks checked against execution/version, under the same task ID with a new execution, preserved history/operation receipts and accepted-input references, and a fresh not-yet-active recovery budget. Require a valid replacement/cleared expiry and reject restart of succeeded/cancelled tasks. Verify duplicate restart requests create one execution and an old execution's controls cannot affect it.
- [ ] 5.6 Implement persisted one-shot scheduling and a reminder handler. Preserve the due instant and zone independently of retry backoff; reject ambiguous/inconsistent time inputs. Verify zero early claims, one catch-up execution after downtime unless expired, and a source event edit leaves the saved time unchanged.
- [ ] 5.7 Start unexpected-worker-loss recovery at the first expired lease's saved expiry, retain the budget across repeated deaths, and fail before another attempt when discovery is too late. Verify process deaths before a reported error cannot loop indefinitely, a long outage requires explicit restart, and graceful release neither starts a budget nor suspends/resets an active one.

## 6. Terminal outcomes and chat delivery

- [ ] 6.1 Commit each terminal outcome and its preallocated message/delivery identity with the run's terminal transition. Verify failures, successes, cancellation, and expiry all have an immutable outcome and recoverable intent, with no terminal state committed alone.
- [ ] 6.2 Implement a transactional local delivery dispatcher with retry backoff, stable message IDs, and duplicate-outcome protection. Interrupt after outcome commit and after publication commit; verify retries yield one message and never rerun the task or alter its outcome.
- [ ] 6.3 Implement owner-scoped ordered/paginated task-message reads that resolve the saved outcome and stable result/file references. Test Main fallback, explicit side-chat delivery, cross-owner denial, and distinct messages for a failed execution and its successful restart.
- [ ] 6.4 Expose pending publication in task detail and link Tasks/Activity to the same saved chat outcome. Record task, run, attempt, operation, and delivery IDs in safe diagnostics, including lease loss, retry exhaustion, and oldest pending delivery; verify logs omit answer bodies and credentials.
